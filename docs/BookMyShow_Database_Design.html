3. Normalization Proof (1NF → BCNF)

1NF ✅

  • All columns contain atomic values (no arrays, no repeating groups).
  • Every table has a primary key.

2NF ✅

  • Every non-key attribute is fully functionally dependent on the entire primary key.
  • show_seats has candidate key (show_id, seat_id): seat_status, locked_until, locked_by all depend on the full composite key.

3NF ✅

  • No transitive dependencies. Example: city_name is not stored in theatres; it is accessed via FK to cities.
  • In shows, prices depend directly on show_id, not derived through movie_id.

BCNF ✅

  • For every FD X → Y, X is a superkey.
  • shows: {screen_id, show_date, start_time} → all attributes. This is a candidate key (UNIQUE constraint).
  • show_seats: {show_id, seat_id} → all attributes. This is a candidate key (UNIQUE constraint).

4. Concurrency & Locking Strategy

4.1 Pessimistic Locking (Primary)

-- Step 1: Acquire exclusive row locks
SELECT * FROM show_seats
WHERE show_id = ? AND seat_id IN (?, ?, ?)
  AND seat_status = 'AVAILABLE'
FOR UPDATE;
-- InnoDB X-locks prevent concurrent access.

-- Step 2: Mark as LOCKED with 5-minute hold
UPDATE show_seats
SET seat_status = 'LOCKED',
    locked_until = NOW() + INTERVAL 5 MINUTE,
    locked_by = ?
WHERE ...;

COMMIT;  -- releases locks
Why pessimistic? For blockbuster opening-day shows, thousands of users target the same seats. SELECT ... FOR UPDATE guarantees zero double-bookings at the database level.

4.2 Timed Holds (5-Minute Window)

User selects seats → LOCKED (5 min) → pays → BOOKED ✓
                                    └→ timer expires → AVAILABLE (released)
  • locked_until stores expiry timestamp.
  • MySQL Event runs every 30s: CALL sp_release_expired_holds().
  • In production, Redis EXPIRE keys provide sub-second precision.

4.3 Idempotent Payment Webhooks

  • UNIQUE constraint on payments.idempotency_key (gateway's event ID).
  • Before processing: check if key exists → if yes, return ALREADY_PROCESSED.
  • Guarantees exactly-once seat confirmation per payment event.

6. P2: Shows at a Theatre on a Date

SET @theatre_id = 1;        -- PVR INOX: Phoenix Palladium
SET @show_date  = '2026-11-18';

SELECT
    m.title           AS movie_title,
    m.language,
    m.genre,
    m.certificate,
    CONCAT(FLOOR(m.duration_minutes / 60), 'h ',
           MOD(m.duration_minutes, 60), 'm')  AS duration,
    sc.screen_name,
    sh.show_id,
    sh.start_time,
    sh.end_time,
    sh.price_regular,
    sh.price_premium,
    sh.price_recliner,
    (SELECT COUNT(*) FROM show_seats ss
     WHERE ss.show_id = sh.show_id
       AND ss.seat_status = 'AVAILABLE') AS available_seats,
    (SELECT COUNT(*) FROM show_seats ss
     WHERE ss.show_id = sh.show_id) AS total_seats
FROM shows sh
    INNER JOIN screens sc ON sh.screen_id = sc.screen_id
    INNER JOIN movies  m  ON sh.movie_id  = m.movie_id
WHERE sc.theatre_id = @theatre_id
  AND sh.show_date  = @show_date
ORDER BY m.title ASC, sh.start_time ASC;

Query Explanation

  • Joins: shows → screens (filter by theatre), shows → movies (movie details).
  • Sub-queries: Count available and total seats per show for the seat map.
  • Index used: idx_show_date_screen (show_date, screen_id) — fast lookup.
  • Order: Movie title then start time (matches BookMyShow UI).
